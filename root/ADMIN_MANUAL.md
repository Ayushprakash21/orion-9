# ORION-9 Admin Manual

## Admin Control Plane
The Admin Control Plane governs the platform. It is separate from the user's day-to-day supply-chain operating workspace.

## Autonomous Operations Governance
Open **Admin → Autonomous Operations** for the central administrative capability map. It provides direct navigation to platform intelligence, security, integrations, data controls, financial governance, automation governance, learning/outcome traceability, and audit surfaces.

### Administrative responsibilities
- Define roles and access boundaries.
- Govern AI agent permissions and delegation.
- Configure Manual / Copilot / Autopilot boundaries.
- Review platform intelligence and integration posture.
- Maintain master-data and data-quality controls.
- Govern financial and execution thresholds.
- Review audit activity and traceability.
- Maintain platform branding and settings.

## User vs Admin boundary
Users operate the supply chain. Admins define the permissions, policies, security, and platform boundaries under which that operation occurs.

## Auditability
Material administrative changes should be traceable through the Audit Activity surface. Decision and outcome history belongs to the operational intelligence layer and should remain governed by platform access controls.

## Safety rule
Never represent an external ERP/WMS/TMS/MES/CRM mutation as completed unless the corresponding connector, permission, and execution policy actually authorize and confirm it.

## ORION-9 OS Controls
- **SHUT DOWN** is available on the authentication footer and starts the same governed ORION-9 shutdown sequence used by the operating system.
- The authentication pages retain the cinematic ORION-9 startup/post-login flow; no generic loading replacement is used.
- The live supply-chain wallpaper uses the procedural globe/network composition with animated orbiting intelligence paths.
