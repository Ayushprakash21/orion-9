# ORION-9 KERNEL ARCHITECTURE

**Version**: 2.0 | **Wave**: Foundation Wave 2 | **Status**: Active

---

## Overview

The Orion-9 Kernel is the internal operating-system execution foundation of the Orion-9 Supply Chain Operating System. Every material operation in Orion-9 must flow through the kernel's canonical execution pipeline, ensuring consistent authentication, authorization, tenant isolation, policy governance, approval gating, state management, event fabric, and audit logging.

---

## Execution Pipeline

Every command follows this execution lifecycle:

```
ACTOR
  ↓
COMMAND
  ↓
IDENTITY RESOLUTION (actor must have non-empty id)
  ↓
IDEMPOTENCY CHECK (duplicate key → return previous result)
  ↓
AUTHORIZATION (role-based permission check, tenant isolation)
  ↓
POLICY EVALUATION (governance rules, AI constitution)
  ↓
APPROVAL REQUIRED?
  ├── YES → ApprovalRequest created → COMMAND HALTS
  │              ↓
  │          Human reviews and approves/rejects
  │              ↓
  │          resolveApproval() called
  │              ↓
  │          Command handler re-executed
  │
  └── NO → continue
       ↓
HANDLER EXECUTION (Supabase or local IndexedDB)
       ↓
STATE ENGINE (validates and applies state transition)
       ↓
EVENT (published to KernelEventBus)
       ↓
AUDIT (recorded in KernelAuditEngine)
       ↓
OUTCOME (CommandResult returned to caller)
```

## Components

### 1. Command Model

**File**: `src/kernel/types.ts`

Every command flowing through the kernel is represented as a `CommandEnvelope`:

```typescript
interface CommandEnvelope<T = any> {
  commandId: string;           // Unique ID auto-generated by CommandBus
  commandType: string;         // e.g. 'CREATE_PURCHASE_ORDER'
  timestamp: string;           // ISO 8601
  actor: {
    id: string;
    type: 'USER' | 'AI_AGENT' | 'SYSTEM' | 'EXTERNAL_INTEGRATION';
    role?: string;
    name?: string;
  };
  tenant: {
    organizationId: string;
    organizationName?: string;
  };
  entityId?: string;           // Resource being acted upon
  entityType?: string;         // e.g. 'purchase_order'
  payload: T;                  // Command-specific data
  correlationId: string;       // Tracing ID (auto-generated if not provided)
  idempotencyKey?: string;     // Prevents duplicate execution
}
```

### 2. CommandBus

**File**: `src/kernel/CommandBus.ts` | **Instance**: `kernelCommandBus`

The central orchestrator. Usage:

```typescript
const result = await kernelCommandBus.dispatch(
  'CREATE_PURCHASE_ORDER',
  { title: 'Equipment', amount: 12_000, currency: 'USD' },
  {
    actor: { id: 'user-001', type: 'USER', name: 'Alice', role: 'buyer' },
    tenant: { organizationId: 'org-acme' },
    entityType: 'purchase_order',
    amount: 12_000,
    idempotencyKey: 'po-acme-q2-001',
    correlationId: 'corr-001',
  }
);

if (result.requiresApproval) {
  // Command halted — show approval pending UI.
  // Later, when manager approves:
  const resumeResult = await kernelCommandBus.resolveApproval(
    result.approvalId,
    'APPROVED',
    { id: 'mgr-001', name: 'Bob Smith', role: 'procurement_manager' }
  );
}
```

**Registering a handler**:
```typescript
kernelCommandBus.registerHandler('MY_COMMAND', async (command) => {
  // Execute business logic.
  return { myResult: true };
});
```

### 3. Authorization Engine

**File**: `src/kernel/authorization/AuthorizationEngine.ts` | **Instance**: `authorizationEngine`

Role-based authorization. Checks that the actor's roles satisfy the required permission for a resource type. Enforces tenant isolation — actors cannot act across organization boundaries.

- **Fail closed**: Unknown permissions are denied.
- **Internal system actors** (id=`orion-kernel`, type=`SYSTEM`) bypass role checks but are still logged.
- **AI agents** are NOT privileged; they go through the same role checks.

### 4. Policy Engine

**File**: `src/kernel/PolicyEngine.ts` | **Instance**: `kernelPolicyEngine`

Evaluates commands against registered governance policies. Returns a `PolicyEvaluationOutcome`:

```typescript
type PolicyEvaluationResult =
  | 'ALLOW'
  | 'ALLOW_WITH_CONTROLS'
  | 'REQUIRE_APPROVAL'
  | 'MASK'
  | 'BLOCK'
  | 'ESCALATE';
```

**Built-in policies** (registered at startup):

| Policy ID | Name | Condition | Outcome |
|-----------|------|-----------|---------|
| POL-FIN-001 | High-Value Financial Threshold | amount > \$50,000 | REQUIRE_APPROVAL |
| POL-FIN-002 | Executive Financial Threshold | amount > \$250,000 | ESCALATE |
| POL-AI-001 | AI Write Guardrail | actor=AI + action=DROP_TABLE/RAW_SQL | BLOCK |
| POL-AI-CONSTITUTION | AI Monetary Gate | actor=AI + amount > \$5,000 | REQUIRE_APPROVAL |
| POL-SUP-001 | Supplier Risk Gate | supplierRiskScore > 75 | REQUIRE_APPROVAL |
| POL-CTR-001 | Contract Commitment | amount > \$100,000 | REQUIRE_APPROVAL |
| POL-PO-001 | PO Standard Amount | amount > \$5,000 | REQUIRE_APPROVAL |
| POL-PO-002 | PO High-Value Senior | amount > \$50,000 | REQUIRE_APPROVAL |
| POL-PO-003 | AI-Generated PO Mandate | actor=AI_AGENT + CREATE_PO | REQUIRE_APPROVAL |

### 5. Approval Engine (built into CommandBus)

When a policy returns `REQUIRE_APPROVAL`:

1. An `ApprovalRecord` is created with status `PENDING`.
2. The original `CommandEnvelope` is stored internally.
3. An `APPROVAL_REQUIRED` event is published.
4. The command returns with `{ requiresApproval: true, approvalId: '...' }`.
5. **Execution is completely halted** — no partial execution, no auto-approval.

**ApprovalRecord**:
```typescript
interface ApprovalRecord {
  approvalId: string;
  commandId: string;
  correlationId: string;
  requester: { id: string; type: string; name?: string; role?: string };
  approver?: { id: string; name: string; role: string };
  policyId?: string;
  entityType: string;
  entityId: string;
  action: string;
  amount?: number;
  status: 'PENDING' | 'APPROVED' | 'REJECTED' | 'CANCELLED';
  createdAt: string;
  decidedAt?: string;
  comments?: string;
}
```

**Approving/rejecting**:
```typescript
// Get all pending approvals.
const pending = kernelCommandBus.getPendingApprovals();

// Resolve an approval (re-executes command if APPROVED).
const result = await kernelCommandBus.resolveApproval(
  approvalId,
  'APPROVED',    // or 'REJECTED'
  { id: 'mgr-001', name: 'Bob Smith', role: 'procurement_manager' },
  'Approved for Q2 equipment budget'
);
```

### 6. State Engine

**File**: `src/kernel/StateMachine.ts`

12 canonical state machines for all transactional entities:

- `poStateMachine` — Purchase Order (`DRAFT → PENDING_APPROVAL → APPROVED → RELEASED → ...`)
- `shipmentStateMachine` — Shipments
- `actionStateMachine` — Actions
- `decisionStateMachine` — Decisions
- `qualityStateMachine` — Quality Inspections
- `invoiceStateMachine` — Invoices
- `vendorStateMachine` — Vendors/Suppliers
- `contractStateMachine` — Contracts
- `scenarioStateMachine` — Stress Test Scenarios
- `yardAppointmentStateMachine` — Dock Appointments
- `consolidationStateMachine` — Freight Consolidation
- `replenishmentOrderStateMachine` — Autonomous Replenishment

**Usage**:
```typescript
// Check transition validity.
const result = poStateMachine.canTransition('PENDING_APPROVAL', 'APPROVED');
// → { valid: true, fromState: 'PENDING_APPROVAL', toState: 'APPROVED' }

// Apply transition (throws on invalid).
const newState = poStateMachine.transition('po-001', 'PENDING_APPROVAL', 'APPROVED', {
  actorId: 'mgr-001',
  correlationId: 'corr-001',
});
```

### 7. Event Fabric

**File**: `src/kernel/EventBus.ts` | **Instance**: `kernelEventBus`

Pub/sub event fabric with in-memory history, IndexedDB persistence, replay, and idempotency.

```typescript
// Publish.
kernelEventBus.publish('PURCHASE_ORDER_APPROVED', payload, {
  actor, tenant, correlationId, entityId, entityType,
});

// Subscribe.
const unsub = kernelEventBus.subscribe('PURCHASE_ORDER_APPROVED', (event) => {
  console.log('PO approved:', event.entityId);
});

// Replay events.
await kernelEventBus.replayEvents({
  eventTypes: ['PURCHASE_ORDER_APPROVED'],
  fromTimestamp: '2026-01-01T00:00:00Z',
});
```

**Standard event types**:
- `PURCHASE_ORDER_CREATED`, `PURCHASE_ORDER_APPROVED`, `PURCHASE_ORDER_REJECTED`, `PURCHASE_ORDER_CANCELLED`
- `APPROVAL_REQUIRED`, `APPROVAL_GRANTED`, `APPROVAL_REJECTED`
- `PURCHASE_ORDER_STATE_CHANGED` (from state machine)
- `CREATE_PURCHASE_ORDER_COMPLETED` (from CommandBus)

### 8. Audit Engine

**File**: `src/kernel/AuditEngine.ts` | **Instance**: `kernelAuditEngine`

Records immutable audit entries for all material commands.

```typescript
// Automatic via CommandBus — but can also record manually:
await kernelAuditEngine.record({
  actor: { id: 'user-001', type: 'USER', name: 'Alice' },
  tenantId: 'org-001',
  action: 'VIEW_REPORT',
  entityType: 'report',
  entityId: 'rpt-001',
  result: 'SUCCESS',
  classification: 'INTERNAL',
});

// Query records.
const records = kernelAuditEngine.getRecords({
  tenantId: 'org-001',
  entityType: 'purchase_order',
  limit: 50,
});
```

**Never recorded**: passwords, API keys, tokens, private credentials.

### 9. Actor Model

Supported actor types:

| Type | Description | Privileged? |
|------|-------------|-------------|
| `USER` | Human user | No — role-based |
| `AI_AGENT` | Autonomous AI agent | No — must get human approval |
| `SYSTEM` | Internal system process | Only `orion-kernel` id bypasses auth |
| `EXTERNAL_INTEGRATION` | ERP/3PL connectors | No — role-based |

> **AI Constitution Rule**: AI agents submitting commands with amount > \$5,000, or any monetary/approval/activate action, are always routed to `REQUIRE_APPROVAL`. AI cannot bypass human governance.

### 10. Error Model

Standardized error codes (`KernelErrorCode`):

| Code | Meaning |
|------|---------|
| `IDENTITY_REQUIRED` | Missing or empty actor id |
| `DUPLICATE_SUPPRESSED` | Idempotency key already processed |
| `UNAUTHORIZED` | Actor's roles do not permit the action |
| `TENANT_ACCESS_DENIED` | Cross-organization access attempt |
| `POLICY_BLOCKED` | Policy returned BLOCK |
| `APPROVAL_REQUIRED` | Policy requires human approval (not an error — expected halting) |
| `APPROVAL_REJECTED` | Human rejected the approval request |
| `HANDLER_NOT_FOUND` | No handler registered for command type |
| `EXECUTION_FAILED` | Handler threw an error during execution |

## Backward Compatibility

All existing services (`ActionEngine`, `DecisionEngine`, `ExceptionEngine`, `WorkflowEngine`) continue to operate unchanged. The kernel wraps and extends; it does not replace. Modules not yet migrated to the CommandBus continue to work through their existing service paths.
